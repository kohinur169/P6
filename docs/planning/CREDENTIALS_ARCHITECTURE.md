# Credentials Architecture — Super Admin Managed (Encrypted)

**Branch:** `arena/02f9dca9-p6`  
**Purpose:** Define how payment processor credentials are stored and managed via Super Admin dashboard with ENCRYPTION_MASTER_KEY encryption.  
**Status:** Authoritative architectural decision — replaces previous environment-variable-only approach for processor credentials.

---

## 1. Core Decision

**Payment processor credentials (API Key, Secret, Merchant ID, Webhook Secret) are managed by Super Admin through the dashboard UI, encrypted with `ENCRYPTION_MASTER_KEY`, and stored in the database.**

Environment variables are used ONLY for infrastructure-level secrets, NOT for per-processor merchant credentials.

---

## 2. Two Layers of Configuration

### Layer A: Environment Variables (Infrastructure Only)

These are set once at deploy time and never changed via UI:

| Variable | Purpose | Set By |
|----------|---------|--------|
| `ENCRYPTION_MASTER_KEY` | Master key to encrypt processor credentials in database | Developer / DevOps at deploy |
| `SUPABASE_URL` | Supabase project URL | Developer / DevOps |
| `SUPABASE_ANON_KEY` | Supabase anonymous key | Developer / DevOps |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase service role key (server-side) | Developer / DevOps |
| `SESSION_SECRET` | Session cookie signing | Developer / DevOps |
| `JWT_SECRET` | JWT token signing | Developer / DevOps |
| `NEXTAUTH_SECRET` | NextAuth session secret | Developer / DevOps |
| `NEXTAUTH_URL` | Application base URL | Developer / DevOps |

### Layer B: Super Admin Dashboard (Application Level)

Super Admin adds/edits payment processor credentials through the UI. Each credential is encrypted before saving to database.

| Field | Encrypted? | Stored In |
|-------|------------|-----------|
| Processor name (NMI, Stripe, Payroc, Maverick, etc.) | No | Database |
| API Key / Client ID | **Yes** (ENCRYPTION_MASTER_KEY) | Database |
| API Secret / Client Secret | **Yes** (ENCRYPTION_MASTER_KEY) | Database |
| Merchant ID | **Yes** (ENCRYPTION_MASTER_KEY) | Database |
| Webhook Secret | **Yes** (ENCRYPTION_MASTER_KEY) | Database |
| Is Enabled / Disabled | No | Database |
| Webhook Endpoint URL | No | Database (generated by platform) |

## 3. Webhook Endpoint URLs — Where They Come From

### 3.1 Your Platform Generates Webhook URLs

Your platform creates webhook endpoint URLs for each payment processor. Example format:

```
https://yourdomain.com/api/webhooks/{processor}/{storeId}
```

| Processor | Webhook URL Example |
|-----------|--------------------|
| Stripe | `https://yourdomain.com/api/webhooks/stripe/merchant_123` |
| Payroc | `https://yourdomain.com/api/webhooks/payroc/merchant_123` |
| Maverick | `https://yourdomain.com/api/webhooks/maverick/merchant_123` |
| NMI | `https://yourdomain.com/api/webhooks/nmi/merchant_123` |
| Airwallex | `https://yourdomain.com/api/webhooks/airwallex/merchant_123` |
| Payoneer | `https://yourdomain.com/api/webhooks/payoneer/merchant_123` |
| Rainforest | `https://yourdomain.com/api/webhooks/rainforest/merchant_123` |

### 3.2 How Webhook URLs Are Created

1. **Super Admin enables a processor** (e.g., Stripe) in the dashboard
2. **Platform generates** the webhook URL: `https://yourdomain.com/api/webhooks/stripe/{storeId}`
3. **Super Admin copies** this URL and pastes it into the payment processor's dashboard (Stripe Dashboard, Payroc Portal, Maverick Portal, etc.)
4. **Processor sends events** to that URL when transactions occur
5. **Your platform verifies** the webhook signature and processes the event

### 3.3 Webhook URL Generation Logic

```typescript
// Example: Generate webhook URL for a processor
const webhookUrl = `${process.env.NEXTAUTH_URL}/api/webhooks/${processorName}/${storeId}
// Result: https://yourdomain.com/api/webhooks/stripe/merchant_123
```

Super Admin does NOT create webhook URLs manually — the platform generates them automatically when a processor is enabled for a store.

## 4. Database Schema for Encrypted Credentials

### Table: `payment_processor_credentials`

```sql
CREATE TABLE payment_processor_credentials (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    company_id UUID NOT NULL REFERENCES companies(id),
    processor_name TEXT NOT NULL, -- 'stripe', 'payroc', 'maverick', 'nmi', etc.
    api_key_encrypted TEXT NOT NULL, -- AES-256-GCM encrypted
    api_secret_encrypted TEXT NOT NULL, -- AES-256-GCM encrypted
    merchant_id_encrypted TEXT, -- AES-256-GCM encrypted (optional)
    webhook_secret_encrypted TEXT, -- AES-256-GCM encrypted (optional)
    webhook_url TEXT NOT NULL, -- Generated by platform, not encrypted
    is_enabled BOOLEAN DEFAULT false,
    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now(),
    created_by UUID REFERENCES users(id), -- Super Admin who added it
    UNIQUE (company_id, processor_name)
);

-- Enable RLS
ALTER TABLE payment_processor_credentials ENABLE ROW LEVEL SECURITY;

-- Policy: Company can only see their own credentials
CREATE POLICY company_isolation ON payment_processor_credentials
    FOR ALL USING (company_id = auth.uid()::uuid OR auth.jwt()->>'role' = 'admin');
```

### Encryption/Decryption Functions

```typescript
// lib/encryption.ts
import crypto from 'crypto';

const MASTER_KEY = Buffer.from(process.env.ENCRYPTION_MASTER_KEY, 'base64');

export function encrypt(text: string): string {
    const iv = crypto.randomBytes(16);
    const cipher = crypto.createCipheriv('aes-256-gcm', MASTER_KEY, iv);
    const encrypted = Buffer.concat([cipher.update(text), cipher.final()]);
    const tag = cipher.getAuthTag();
    return Buffer.concat([iv, tag, encrypted]).toString('base64');
}

export function decrypt(encryptedBase64: string): string {
    const data = Buffer.from(encryptedBase64, 'base64');
    const iv = data.subarray(0, 16);
    const tag = data.subarray(16, 32);
    const encrypted = data.subarray(32);
    const decipher = crypto.createDecipheriv('aes-256-gcm', MASTER_KEY, iv);
    decipher.setAuthTag(tag);
    return Buffer.concat([decipher.update(encrypted), decipher.final()]).toString();
}
```

## 5. Super Admin Credential Management Flow

### Step-by-Step:

1. **Super Admin logs in** to dashboard at `/admin/payment-processors`
2. **Clicks "Add Processor"** → selects processor (Stripe, Payroc, Maverick, etc.)
3. **Enters credentials:**
   - API Key / Client ID
   - API Secret / Client Secret
   - Merchant ID (optional, processor-dependent)
   - Webhook Secret (optional, processor-dependent)
4. **Platform generates webhook URL** automatically
5. **Super Admin clicks "Save"**
6. **Platform encrypts** all sensitive fields with `ENCRYPTION_MASTER_KEY`
7. **Encrypted values saved** to `payment_processor_credentials` table
8. **Platform displays** the webhook URL for Super Admin to copy into processor's dashboard

### Editing Credentials:

1. Super Admin opens existing processor config
2. Enters new values (or leaves blank to keep current)
3. Platform re-encrypts and updates database

### Disabling a Processor:

1. Super Admin toggles `is_enabled = false`
2. Platform stops routing payments to that processor
3. Credentials remain encrypted in database (not deleted)

## 6. API Endpoint for Webhook (Example)

```typescript
// src/app/api/webhooks/stripe/[storeId]/route.ts
export async function POST(request: Request, { params }: { params: { storeId: string } }) {
    // 1. Get encrypted credentials from database
    const credentials = await getProcessorCredentials(params.storeId, 'stripe');
    
    // 2. Decrypt webhook secret
    const webhookSecret = decrypt(credentials.webhook_secret_encrypted);
    
    // 3. Verify signature BEFORE parsing body
    const signature = request.headers.get('stripe-signature');
    const body = await request.text(); // Raw body for signature verification
    
    // 4. Verify webhook signature
    const event = stripe.webhooks.constructEvent(body, signature, webhookSecret);
    
    // 5. Process event (idempotency check)
    // 6. Return 200 OK
}
```

## 7. Environment Variables That REMAIN

Only these stay as environment variables (NOT in Super Admin UI):

| Variable | Why Not in Super Admin |
|----------|----------------------|
| `ENCRYPTION_MASTER_KEY` | This is the key that encrypts everything — must exist before any encryption can happen |
| `SUPABASE_*` | Database connection — needed before app starts |
| `SESSION_SECRET` / `JWT_SECRET` | Session security — infrastructure level |
| `CLOUDFLARE_TURNSTILE_*` | Third-party verification — platform-level |
| `SHOPIFY_API_*` / `WC_PAYMENT_API_*` | Platform-level app credentials |

---

## 8. Security Rules

| Rule | Implementation |
|------|---------------|
| Never store plain-text API keys in database | All credential fields encrypted with AES-256-GCM |
| `ENCRYPTION_MASTER_KEY` never stored in database | Only in environment variable |
| Super Admin cannot view decrypted credentials | UI shows masked values (last 4 chars only) |
| Webhook signature verified before processing | HMAC check on raw body |
| RLS on credentials table | Company-scoped access only |
| Audit log for credential changes | Records who changed what and when |

| Where do webhook URLs come from? | Platform generates them: `https://yourdomain.com/api/webhooks/{processor}/{storeId}` |
